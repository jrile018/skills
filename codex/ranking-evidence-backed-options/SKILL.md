# Ranking Evidence-Backed Options

## Principle

A useful ranking makes the user’s objective, evidence, uncertainty, and tradeoffs visible. A precise-looking score without those elements is false confidence.

## Ranking Contract

1. State the decision being optimized and any hard constraints.
2. Choose 3–6 criteria that affect that decision. Define each criterion before scoring.
3. Ask for weights only when different reasonable weights would materially change the winner; otherwise state sensible weights and proceed.
4. Verify facts that can change, such as open roles, current affiliations, publication records, program requirements, and product availability.
5. Separate:
   - **fact** — directly supported by a source;
   - **inference** — reasoned from facts;
   - **unknown** — not verified.
6. Normalize scores to one scale and show the weighted total. Do not hide a hard constraint inside an average.
7. Stress-test the top choices by changing the most uncertain weight or assumption.
8. End with a ranked shortlist and concrete next actions.

## Output Shape

| Rank | Option | Key scores | Evidence | Main upside | Main risk | Confidence | Next action |
|---:|---|---|---|---|---|---|---|

Follow the table with:

- **Best overall** and why.
- **Best alternative** if the user values a different tradeoff.
- **What would change the ranking**, including missing evidence.
- A copy/paste action list for applications, outreach, experiments, or due diligence.

## Domain Adjustments

- Research questions: emphasize novelty, falsifiability, tractability, data access, and advisor fit.
- Professors or laboratories: emphasize topic fit, mentoring access, recent work, network relevance, and realistic entry route.
- Companies or roles: emphasize role fit, hiring requirements, interview language, location, timing, and user priority.
- Projects: emphasize expected value, learning, differentiation, dependencies, and time to demonstrable result.

## Example

When ranking research directions, a prestigious topic with no available data may lose to a slightly less novel question that has a clear falsification test, an accessible advisor, and a feasible first experiment.

## Common Mistakes

- Ranking before defining the decision.
- Using citation counts or brand recognition as universal proxies for fit.
- Treating stale web information as current.
- Presenting inferred relationships as confirmed connections.
