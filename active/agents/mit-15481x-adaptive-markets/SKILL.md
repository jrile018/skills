# MIT 15.481x Adaptive Markets

Use the Adaptive Markets Hypothesis as a framework for competing explanations and falsifiable research—not as a trading signal or a claim that every outcome is adaptive.

## Analyze the System

1. Define the market, horizon, participants, information, incentives, constraints, and environmental change under discussion.
2. State the efficient or rational baseline before identifying a deviation.
3. Map the proposed mechanism: behavior or constraint, opportunity, competitors, capacity, liquidity, leverage, feedback, and failure condition.
4. Generate competing explanations such as factor exposure, nonlinear payoff, risk compensation, selection, stale marks, crowding, or data mining.
5. Convert the narrative into observable implications and evidence that could distinguish the explanations.
6. Separate historical course interpretation from current claims; browse fresh authoritative sources when current facts matter.

Read [references/course-guide.md](references/course-guide.md) for the course concept map, hedge-fund return decomposition, systemic-risk chain, research questions, provenance, and evaluation cases.

## Invariants

- Changing efficiency is not proof of exploitable alpha.
- Behavioral terminology is not a causal explanation by itself.
- Residual return after one factor model is not automatically manager skill.
- Analyze liquidity and leverage jointly when forced selling or systemic feedback is possible.
- Distinguish individual-fund risk from market-wide amplification.
- State ethical, governance, incentive, and distributional effects when they are material.
- Do not convert dated examples or theory into a present-day security recommendation.

## Boundaries

This skill owns adaptive interpretation, hedge-fund ecology, market behavior, crowding, crises, and systemic mechanisms. It does not own derivative pricing, mathematical portfolio optimization, production backtesting, current regulation, fund administration, due diligence on a named live fund, or execution.

This skill owns high-level falsifiable test design: observable implications, competing explanations, required data, information timing, and evidence that would distinguish them. Add a quantitative-method skill only when the user requests an execution-ready econometric specification, dependence-valid inference, estimation, code, or implementation. If the request needs current market facts, use fresh sources and label inference.
